# 实用版：先完成一次有质量的训练与提交

原版保留在 `task2_kaggle.py`；建议当前课设使用 `task2_kaggle_practical.ipynb` 或 `task2_kaggle_practical.py`，不再默认执行两个 Large 模型的五折训练。

默认配置为 ImageNet-22K 预训练的 ConvNeXt-Base，224 分辨率训练最多 20 轮，288 分辨率低学习率精调最多 5 轮。先生成五个分层分组划分，但**默认只训练其中第 0 折**：约 80% 训练、20% 验证，是单个模型，不是五折训练。保留 Mixup、EMA、适度人脸增强、最佳模型选择、TTA、重复图像分组隔离和标签无冲突的完全相同图像复用。连续 6 轮验证准确率未提升会结束当前阶段。

官方模型卡：https://huggingface.co/timm/convnext_base.fb_in22k_ft_in1k

默认每 GPU 微批量从 1 改为 8，累积 4 次，在 T4×2 上有效 batch 仍为 64；每轮微批次数从约 11,310 降为约 1,414。批次数减少不等于总训练计算量同比减少，但可以减少调用及多卡同步开销。模型本身更小，取消默认多模型/多折，训练总量大幅下降。真实耗时仍取决于 Kaggle GPU、软件环境和 I/O，需用首轮完整日志估算；不能据未实测的估算承诺完成时间或准确率。

使用：在 Kaggle 导入新版 Notebook，开启 T4×2 和 Internet，并加入 `task2forml`。也可直接复制新版 Python 文件到代码单元格，或执行：

```python
!python -u /kaggle/input/你的代码数据集名称/task2_kaggle_practical.py
```

输出：`/kaggle/working/task2_practical_output/submission.csv`。新版使用新的输出目录，避免与原版 Large 模型检查点混用。默认训练完一个划分即可生成提交，不需要等五折全部完成。

增加了这些日志：启动、全量图像检查进度、依赖加载、模型构建及下载、首批数据读取、每 25 批训练进度与本轮剩余训练时间、验证和断点保存。依赖安装或权重下载等待期间每 30 秒输出心跳。心跳只说明进程尚在该步骤，不代表下载一定取得进展。批次日志中的 ETA 只包括训练，不包括验证、保存和最终 TTA；最初几批的估计易受 GPU 初始化影响。

如果**新版已经显示启动日志后十分钟没有任何后续输出**，应检查 Kaggle 是否仍在运行、是否出现异常、是否启用了 Internet，以及 GPU 使用状态。如果作业界面连启动日志都没有，可能是界面日志尚未显示、容器准备或代码单元格未执行；现有截图不能区分这些原因。可以回到 Edit 的实际运行单元格查看输出，或在独立单元格运行 `!nvidia-smi` 查看 GPU 显存和利用率。避免重新 Run All 同时启动第二份训练。

原版首条训练进度要到 300 个微批次后才打印，所以看不到 batch 日志不一定意味着未训练。但原版图像统计会在训练前打印；如果连数据统计都没有，不能仅用 300 批日志间隔解释。

如显存不足，使用 `--batch-per-gpu 4 --accum 8`，并换一个新的 `--output` 目录以保持检查点配置一致。默认每轮耗时确定后，可按 `20 × 224阶段每轮耗时 + 5 × 288阶段每轮耗时 + 最终推理` 估算总时长，早停可能缩短时间。

完成一次实测提交后，如准确率值得继续提高，可用 `--folds all` 升级为该 Base 模型的五折训练；已有相同配置的第 0 折会自动跳过。`--folds all --ensemble-only` 只在全部五折完成后融合。跨会话保存、复制结果的方法沿用原版说明，但目录改为 `task2_practical_output`。
